Web Application Endpoints Documentation
Overview:
Endpoints in this application serve either HTML pages (rendered views) or API data. They are categorized by access level and functionality, allowing a clear understanding of which parts of the system are publicly accessible, role-protected, or student-specific.
Categories:
    Public Pages: Accessible to anyone, no authentication required.
    Student Pages: Accessible only to users with the STUDENT role (protected via JWT / Spring Security).
    Admin / Superadmin Pages: Accessible only to users with ADMIN or SUPERADMIN roles.
    Mixed / General Pages: Some pages are viewable by multiple roles, depending on authorization.
Each endpoint is documented with:
    URL – the path users navigate to.
    Purpose – what the page or endpoint is for.
    Input – query parameters, path variables, or request body.
    Output – the HTML page rendered, or JSON/API response.
    Access – roles allowed to access the endpoint.

Detail Explaination for Each end points:

Admin Settings API Documentation
Base Path: /api/admin/settings
    GET /payment

        Purpose:
        Retrieve the current payment-related settings configured by the administrator.

        Input:
        No request body required.

        Output:
        Returns a PaymentAdminSetting object containing the current configuration (e.g., payment methods, QR path, or related details).

        Use Case:
        Used by the frontend/admin dashboard to display existing payment configurations.

    PUT /payment
    
        Purpose:
        Update the system’s payment settings.

        Input:
        Request Body: PaymentAdminSetting JSON object with updated configuration values.

        Output:
        Returns the updated PaymentAdminSetting object after saving changes.

        Use Case:
        Used by administrators to modify payment-related settings (e.g., bank info, QR code reference).

    POST /payment/upload

        Purpose:
        Upload a new QR code image for payment (e.g., bank transfer QR).

        Input:
        Multipart Form Data:

        file: the image file (e.g., .png, .jpg) to upload.

        Output:
        Returns FileUploadResponse containing the public path/URL of the uploaded file.

        Use Case:
        Allows admins to update payment QR codes displayed to students/users.

    GET /enrollment

        Purpose:
        Retrieve the current enrollment-related settings configured by the administrator.

        Input:
        No request body required.

        Output:
        Returns an EnrollmentAdminSetting object containing the current configuration (e.g., enrollment dates, limits, or conditions).

        Use Case:
        Used by the frontend/admin dashboard to view enrollment-related configurations.

    PUT /enrollment

        Purpose:
        Update enrollment-related settings.

        Input:
        Request Body: EnrollmentAdminSetting JSON object with new values.

        Output:
        Returns the updated EnrollmentAdminSetting object after saving changes.

        Use Case:
        Allows admins to adjust enrollment periods, requirements, or other parameters.

Admin User Management API

Base Path: /admin/users

    POST /{id}/reset-password

        Purpose:
        Reset a user’s password using a new password provided by a superadmin.

        Input:
        Path Variable: id (Long) → User ID to reset.
        Request Body: JSON with newPassword key.

        Output:
        JSON message confirming password reset:
            {
            "message": "Password has been reset successfully.",
            "userId": 123
            }

        Use Case:
            Allows superadmins to directly reset user passwords for account recovery or administrative purposes.
    POST /{id}/roles/{role}/grant

        Purpose:
        Grant a specific role to a user.

        Input:
        Path Variable: id (Long) → User ID.
        Path Variable: role (String) → Role to assign.

        Output:
        JSON message confirming role assignment:
            {
            "message": "Role granted successfully.",
            "userId": 123,
            "role": "ADMIN"
            }

        Use Case:
            Used by superadmins to assign permissions/roles to users dynamically.

    POST /{id}/roles/{role}/revoke

        Purpose:
        Revoke a specific role from a user.

        Input:
        Path Variable: id (Long) → User ID.
        Path Variable: role (String) → Role to remove.

        Output:
        JSON message confirming role revocation:
            {
            "message": "Role revoked successfully.",
            "userId": 123,
            "role": "ADMIN"
            }

        Use Case:
            Allows superadmins to remove permissions/roles from users when needed.

    GET /

        Purpose:
            Retrieve a paginated list of all users.

        Input:
            Optional pagination parameters: page, size, sort.

        Output:
            Page<UserDto> containing user summaries.

        Use Case:
            Used by admins or users with USER_READ authority to view all registered users.

    GET /{id}

        Purpose:
            Retrieve detailed information of a single user by ID.

        Input:
            Path Variable: id (Long) → User ID.

        Output:
            User object if found, or 404 Not Found if the user doesn’t exist.

        Use Case:
            View specific user details for administrative purposes.

    POST /create

        Purpose:
            Create a new user in the system.

        Input:
            Request Body: JSON with required user information (e.g., name, email, password).

        Output:
            JSON containing created user’s fullName and email, or error message if creation fails.

        Use Case:
            Superadmins can add new users to the system.

    PUT /{id}

        Purpose:
            Update an existing user’s details.

        Input:
            Path Variable: id (Long) → User ID.
            Request Body: User object with updated data.

        Output:
            Updated User object.

        Use Case:
            Modify user information such as name, email, or other profile details.

    DELETE /{id}

        Purpose:
            Delete a user from the system.

        Input:
            Path Variable: id (Long) → User ID.

        Output:
            No content (204 No Content) on successful deletion.

        Use Case:
            Remove inactive or invalid users from the system.

    GET /me

        Purpose:
            Retrieve information of the currently authenticated user.

        Input:
            No input required; uses authentication context.

        Output:
            UserDto of the currently logged-in user.

        Use Case:
            Used by users to view their own profile and roles.

Announcement Management API

Base Path: /api/announcements

    POST /create

        Purpose:
            Create a new announcement with optional description, PDF attachment, and scheduling details.

        Input:
            Request Parameters:
            title (String) → Announcement title.
            description (String, optional) → Detailed description.
            pdf (MultipartFile) → PDF file associated with the announcement.
            publishDate (LocalDateTime, optional) → Scheduled start date.
            expiryDate (LocalDateTime, optional) → Scheduled end date.

        Output:
            Returns the created Announcement object with all its details.

        Use Case:
            Allows admins or superadmins to create announcements for users with optional scheduling and document attachment.

    GET /active

        Purpose:
            Retrieve all currently active announcements.

        Input:
            No input required.

        Output:
            List of active Announcement objects.

        Use Case:
            Display active announcements to end users on dashboards or portals.

    GET /download/{fileName}

        Purpose:
            Download the PDF file associated with a specific announcement.

        Input:
            Path Variable: fileName (String) → Name of the file to download.

        Output:
            FileSystemResource containing the requested PDF.
            Returns 404 Not Found if the file doesn’t exist.

        Use Case:
            Allows users to download announcement attachments for reference or record-keeping.

    DELETE /delete/{id}

        Purpose:
            Delete an existing announcement.

        Input:
            Path Variable: id (Long) → Announcement ID to delete.

        Output:
            JSON message confirming deletion: "Deleted successfully".

        Use Case:
            Enables admins or superadmins to remove outdated or incorrect announcements.

Authentication API

Base Path: /auth

    POST /login

        Purpose:
            Authenticate a user with email and password, and generate a JWT token for session management.

        Input:
            Request Body: LoginUserDto JSON object containing:
            email (String) → User email for login.
            password (String) → User password.

        Output:
            LoginResponse JSON object containing:
            token (String) → JWT token for authenticated session.
            expiresIn (Long) → Token expiration time in milliseconds.
            admin (Boolean) → Whether the user is an admin.

        Use Case:
            Allows users to log in to the system securely.
            Provides a JWT for subsequent authenticated API requests.
            Supports identifying admin users for role-based access control.

Enrollment API
Base Path: /api

    POST /enrollments

        Purpose:
            Submit a new enrollment application for a fresher student.

        Input:
            Request Body: EnrollmentRequestFresher JSON containing enrollment details (dto) and associated files.
            Authenticated User: CustomUserDetails (student submitting the enrollment).

        Output:
            JSON success response: "Enrollment successful".

        Use Case:
            Allows students to submit enrollment applications for processing.

    POST /pre_enrollments

        Purpose:
            Create a pre-enrollment record for a new student with a pass certificate file.

        Input:
            Request Part: dto → RequestPreEnrollmentDTO object with pre-enrollment data.
            Request Part: passCertificate → Image file of the student’s certificate.

        Output:
            JSON success response: "Pre-enrollment successful" or error response if creation fails.

        Use Case:
            Enables students to submit initial pre-enrollment information before full enrollment.

    POST /pre_enrollments_old

        Purpose:
            Create a pre-enrollment record for returning/old students with ID card upload.

        Input:
            Request Part: dto → RequestPreEnrollmentOldDTO with old student data.
            Request Part: studentIdCardUrl → Image file of student ID card.

        Output:
            JSON success response: "Pre-enrollment (old) created successfully" or error response if creation fails.

        Use Case:
            Supports returning students in submitting pre-enrollment information.

    POST /admin/enrollments/{id}/accept

        Purpose:
            Accept a student’s enrollment application by admin or superadmin.

        Input:
            Path Variable: id (Long) → Enrollment ID.
            Authenticated User: CustomUserDetails (admin processing the enrollment).

        Output:
            JSON success response: "Enrollment accepted" or error if operation fails.

        Use Case:
            Admins use this endpoint to approve enrollment applications.

    POST /admin/enrollments/{id}/reject

        Purpose:
            Reject a student’s enrollment application with optional remark by admin or superadmin.

        Input:
            Path Variable: id (Long) → Enrollment ID.
            Request Parameter: remark (String, optional) → Reason for rejection.
            Authenticated User: CustomUserDetails (admin processing the enrollment).

        Output:
            JSON success response: "Enrollment rejected" or error if operation fails.

        Use Case:
            Admins use this endpoint to deny enrollment applications while optionally providing a reason.

Admin File Upload Access API

Base Path: /api/uploads
Access: ADMIN, SUPERADMIN

    GET /{filename}

        Purpose:
            Serve uploaded files for admin or superadmin users, with optional forced download.

        Input:
            Path Variable: filename (String) → Name of the file inside the uploads directory.
            Request Parameter: download (boolean, optional, default false) → true to force download, false for inline viewing.
            Authenticated User: CustomUserDetails (role ADMIN or SUPERADMIN).

        Output:
            Returns the requested file as a Resource with appropriate content type.
            Sets content disposition based on download parameter.
            Cache-Control header set to 7 days.

        Error Responses:
            401 Unauthorized if not authenticated.
            400 Bad Request for invalid file names or paths.
            404 Not Found if file does not exist.
            500 Internal Server Error for file access issues.

        Use Case:
            Allows admins to securely access and download files uploaded to the system, with safe handling against path traversal and forced downloads.
